# CLAUDE.md

## Project Overview

`@nyby/meteor-react-js` — A browser-compatible Meteor DDP client for React apps, forked from `@meteorrn/core`. Provides DDP connectivity, Minimongo collections, reactive Tracker, Accounts, and React hooks (`useTracker`, `usePublication`, `useMethod`).

## Tech Stack

- **Language**: TypeScript (source in `src/`)
- **Build**: Babel (with `@babel/preset-typescript`, `@babel/preset-env`, `@babel/preset-react`)
- **Tests**: Mocha + Chai + Sinon (test files use Jest-style mocks in some places)
- **Formatter**: Prettier (`printWidth: 120`, `singleQuote: true`)
- **Package manager**: npm (both `package-lock.json` and `yarn.lock` exist; prefer npm)

## Commands

- `npm install` — Install dependencies
- `npm run prepare` — Build dist (cleans `dist/`, runs Babel on `src/`, copies `index.d.ts`)
- `npm run build:tsc` — TypeScript type-check only (`tsc -p tsconfig.build.json`)
- `npm run format` — Run Prettier on `src/` and `test/`
- `npx mocha --require test/setup.js test/**/*.test.js` — Run tests

## Project Structure

```

  components/

```

## Code Conventions

- Single quotes, 120 char line width (Prettier enforced)
- TypeScript source with `.ts` extension; imports use `.js` suffix (for ESM compatibility)
- The `Meteor` object is a plain object literal (not a class) exported from `Meteor.ts`
- Heavy use of `any` casts for DDP/minimongo interop — this is intentional, not something to "fix"
- React hooks follow `use*` naming; HOC uses `withTracker`
- Collections support bulk operations (`updateMany`, `bulkUpdate`) with automatic server-method fallback

## Important Notes

- The `dist/` folder is the published artifact (generated by `npm run prepare`); do not edit it directly
- `index.d.ts` in `src/` is the public API type surface — keep it in sync with actual exports
- The DDP layer uses `wolfy87-eventemitter` for events and `@meteorrn/minimongo` for local data
- `WebSocket` is expected to be available globally (browser environment)
